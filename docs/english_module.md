# Модуль английского языка: устройство и эксплуатация

## Возможности пользователя

Материалом служат JSON-словари из `resources/words/` или выбранные в графовом
редакторе пользовательские JSON-файлы. Из одного словаря приложение может
построить четыре независимых упражнения:

1. словарный диктант «перевод → английский термин» с повтором ошибок;
2. заполнение пропусков в предложениях;
3. выбор правильной IPA-транскрипции;
4. произношение вслух с записью микрофона и сравнением с WAV-эталонами.

У авторизованного пользователя диктант учитывает статистику прошлых сессий:
ошибочные и давно не встречавшиеся слова получают больший вес. Для гостя эта
статистика живёт только до закрытия приложения.

## Формат словаря и собственный звук

Рекомендуемый формат:

```json
{
  "unit": 1,
  "title": "My vocabulary",
  "vocabulary": [
    {
      "term": "network",
      "translation": "сеть",
      "transcription": "/ˈnetwɜːk/",
      "audio": "audio/network.wav",
      "speak_as": "network"
    }
  ]
}
```

`transcription`, `audio` и `speak_as` необязательны. Относительный `audio`
разрешается от каталога самого JSON. Поддерживается только несжатый WAV;
пользовательский файл имеет приоритет над общей поставкой. Абсолютный путь
работает только на текущем компьютере, поэтому для переносимого словаря нужно
держать JSON и подпапку `audio/` вместе.

В редакторе Июля откройте узел «Слова из файла» → «Просмотр/правка», выберите
строку и нажмите «Выбрать WAV для строки…». При сохранении поле `audio`
записывается в JSON.

## Как устроено выполнение

`bootstrap.py` сканирует `resources/words/*.json`, определяет тип файла и
создаёт разделы. Раздел транскрипции появляется только при наличии IPA, а
раздел произношения — только если найден хотя бы один WAV.

Доменные генераторы находятся в `exercises/english/generators.py`. Они создают
обычные контракты ядра: `InteractiveTask` для длинного диктанта и `StaticTask`
с `VoiceSpec` для отдельного голосового ответа. Звук показывается универсальным
`AudioBlock`; захват микрофона выполняет платформенный `VoiceRecorder`.

В языке Июль `words_file` выдаёт `WORDS`, `words_pick` разбирает одну пару, а
`words_trainer` завершает граф интерактивной сессией. Пользовательские аудио
переносятся вместе со значением словаря до тренажёра.

## Проверка произношения

Это локальное сопоставление короткой записи, а не облачное распознавание речи:

1. WAV читается, сводится в mono и приводится к 16 kHz;
2. удаляется тишина, звук режется на окна 25 ms с шагом 10 ms;
3. из каждого окна извлекаются MFCC-признаки;
4. DTW выравнивает произнесённое слово и эталоны по времени;
5. расстояние до целевого слова сравнивается с соседними словами словаря.

Поскольку слово уже показано, используется guided matching, но первое место
само по себе не означает успех: требуется измеримый отрыв. Небольшое второе
место допускается лишь внутри доли расстояния между эталонами. Тишина,
нечитаемый WAV и отсутствие эталонов отличаются от неверного произношения.

MFCC/DTW не умеет указать неверную фонему или поставить артикуляцию. Для такой
обратной связи потребуется фонемное ASR либо внешний speech assessment API.

## Повторная генерация поставочных WAV

Генерация выполняется заранее; приложение ученика TTS не запускает.

1. Установите Python-зависимости проекта и `espeak-ng` так, чтобы команда
   `espeak-ng --version` работала в новом терминале.
2. Из корня репозитория проверьте доступность backend:

   ```powershell
   where.exe espeak-ng
   python tools/generate_audio.py --help
   ```

3. Пересоберите все эталоны:

   ```powershell
   python tools/generate_audio.py --backend espeak --rate 16000 --force
   ```

4. Для одного словаря используйте:

   ```powershell
   python tools/generate_audio.py --dict resources/words/term_4_unit1_internet.json --backend espeak --rate 16000 --force
   ```

Результат записывается в `resources/audio/`, а соответствие терминов файлам —
в `resources/audio/index.json`. `--force` обязателен для замены существующих
файлов; без него они переиспользуются. Скрипт приводит результат к mono PCM16,
16 kHz и обрезает только длинную тишину, сохраняя безопасный хвост после речи.

Не добавляйте сотни заново созданных WAV в обычный code-only PR, если площадка
не принимает бинарные файлы. Их следует выпускать отдельным архивом, Git LFS
или самостоятельным пакетом ресурсов.

## Диагностика Windows

Код `0xC0000409` означает аварийное завершение нативного компонента, а не
обычное Python-исключение. Опрос микрофона теперь отложен до нажатия
«Записать», а захват использует `preferredFormat()` устройства — открытие
режима «Решать» не должно обращаться к драйверу ввода.

Если падение происходит уже после нажатия «Записать», проверьте разрешение на
микрофон для классических приложений Windows, обновите аудиодрайвер и временно
отключите виртуальные устройства/аудиоулучшения. В таком случае важны точный
момент падения и название активного устройства, потому что Python не получает
исключение от аварийно завершившегося Qt multimedia backend.
